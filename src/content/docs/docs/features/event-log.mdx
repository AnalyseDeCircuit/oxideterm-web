---
title: Notifications and Audit
description: Inspect operation history, outcomes, related sessions, and protected detail exports.
---

Open **Notifications & Audit** from the activity bar or use the command palette's event-log action. Notifications show recent messages; **Audit**, **Sessions**, and **Session recordings** provide history and playback.

## Collect Operation History

1. Select **Audit** and enable **Enable audit**. It starts off and records subsequent operations.
2. Perform the connection, command, file, or forwarding operation, then return and click **Refresh**.
3. Filter by category, severity, source, outcome, and time. Choose the search field, enter a query, and press Enter.
4. Open a record to inspect its target, source, result, and evidence. **Sent** means input was delivered; an exit code or protocol result establishes completion more directly.
5. Use **Sessions** to find related operations and recordings for a session.

Time filters include today, the week, the month, and all retained history. Searching and filtering do not delete records. Connection state and reconnect progress are also available in [Runtime](/docs/features/connection-monitor/).

## Retention

Disabling audit stops collection but keeps existing history readable. Operation records default to **90 days** and **512 MiB**. Set retention and capacity in the page's settings, then save. Export records you need before clearing them or reducing retention.

Terminal output requires a separate **Record terminal output** switch and confirmation; see [Session Recording](/docs/features/recording/). It is not collected merely because the audit page is open.

## Export

Use **Export summaries as JSON** or **Export summaries as CSV** for the selected filters. **Export protected details** asks for confirmation and includes commands, paths, endpoints, accounts, and operation details in a plaintext file. It does not include session recordings.

Review exported files before sharing them. A failed operation's target and evidence are useful for diagnosis, while credentials and unrelated private content do not belong in a support report.
