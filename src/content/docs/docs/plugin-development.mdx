---
title: Plugin Development Guide
description: Build native process, Wasm, and manifest-only plugins for OxideTerm.
---

Native plugins are not React components and do not execute JavaScript in a WebView. The host discovers a `plugin.json` package, then activates a host-owned process or Wasm runtime when requested.

## Start with a manifest

Create `<config-dir>/plugins/com.example.hello/plugin.json`:

```json
{
  "id": "com.example.hello",
  "name": "Hello Native",
  "version": "0.1.0",
  "runtime": { "kind": "wasm", "entry": "plugin.wasm" },
  "contributes": {
    "sidebarPanels": [{ "id": "hello", "title": "Hello", "icon": "panel-left" }],
    "settings": [{ "id": "message", "type": "string", "default": "Hello", "title": "Message" }]
  }
}
```

Use `runtime.kind` `wasm`, `process`, or `manifest-only`. Every runtime has an explicit entry path. Legacy `main.js` packages are retained for migration diagnostics only and are never executed.

## Process plugins

Process plugins use host-owned stdin, stdout, and stderr. Stdout carries one versioned JSON object per line; stderr is reserved for diagnostics. The host sends activation, event, command, health, and shutdown requests, and the plugin responds with the same request identifier.

```text
Host stdin  -> activate / sendEvent / dispatchCommand / health
Plugin stdout -> runtimeReady / contribution registrations / responses
Plugin stderr -> diagnostics
```

## Native UI and host APIs

Plugins declare tabs, sidebar panels, settings, commands, keybindings, context menus, status items, terminal hooks, subscriptions, AI tools, and transports. A tab or panel registers a declarative schema; GPUI renders it. Plugins never receive GPUI elements or CSS injection privileges.

During activation, the host provides the effective capabilities and allowed host APIs. Request only the access your package needs. Keep secrets in secret-aware host flows and never write them to protocol frames or diagnostics.

## Develop and test

1. Run `oxideterm paths --json` and place the package in the reported `plugins` directory.
2. Enable or reload it from the desktop Plugin Manager.
3. Keep process protocol output on stdout and diagnostics on stderr.
4. Use `oxideterm plugins list --json` and `oxideterm plugins enable <id> --dry-run` for headless checks.

The native plugin protocol evolves with the application. Validate against the current release before publishing a package.
