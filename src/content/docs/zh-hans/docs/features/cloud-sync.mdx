title: 云同步与备份
description: 在设备间共享选定配置，处理冲突，并保存加密备份。
---

云同步用于共享选定配置，`.oxide` 加密文件用于独立备份或一次性迁移；两者都不恢复运行中的终端或远端进程。

## 配置第一台设备

1. 打开**云同步 → 配置**，选择 WebDAV、S3、Git、GitHub Gist、Dropbox、OneDrive、Google Drive 或 HTTP JSON。“本地文件”用于手动导入导出。
2. 填写存储位置和凭据，选择设备间共用的命名空间、文件夹或前缀。
3. 设置同步密码，用于加密配置，与存储服务的登录密码或令牌不同。
4. 按需选择连接、转发、快捷命令、传输配置、应用设置和插件设置。环境变量与敏感凭据需要单独选择。
5. 保存后点击**同步**，检查预览，再选择**应用并同步**。确认结果后再开启自动上传。

首次创建私有 Gist 后，记下它的 ID，供其他设备使用。HTTP JSON 服务需要支持当前的列表、读写和删除协议。

## 添加其他设备

配置相同后端、存储位置、命名空间和同步密码，并为该设备单独登录存储服务。同步、检查冲突后应用。如果没有同步凭据，在新设备上补充；私钥文件路径也可能需要调整。

插件连接配置不会自动安装插件，各设备需要自行安装并启用对应提供方。本地 Shell 程序路径和窗口标签范围留在当前设备；快捷命令分组外观随受支持的分组数据迁移。

## 冲突与中断

独立修改会合并，同一字段存在竞争修改时，在预览中选择保留版本。未解决的冲突继续使用当前本地值。关闭某个同步类别只会排除它，不删除远端记录。

| 问题 | 下一步 |
| --- | --- |
| 存储服务认证失败 | 检查登录、令牌、端点和存储权限。 |
| 无法解密 | 与另一设备核对位置和同步密码。 |
| 本地已应用，但上传失败 | 再次同步以重试发布。 |
| 应用过程中中断 | 重新打开应用完成恢复，再重试；仍受阻时保留恢复文件。 |
| HTTP JSON 提示升级 | 先升级服务器再重试。 |

更改同步密码时，会先创建并验证新同步空间，再切换过去；旧空间保留。其他设备需更新命名空间和密码。上传失败后，用同一个新密码重试。

## 加密备份

选择“本地文件”，设置归档密码和内容，保存后使用“导出到本地文件”。恢复时选择“从本地文件导入”，解密、查看预览、选择记录和冲突策略后确认。回到远程同步时，重新保存远程后端配置。

版本 2 `.oxide` 文件将名称等元数据与载荷一同加密，仍可读取版本 1 归档。凭据和私钥需要单独勾选导入导出选项，文件与密码应分开保存。

归档包含选定配置，不是完整数据目录或录制历史。需要完整本地副本时，关闭应用和 CLI，从设置或 `oxideterm paths --json` 查找实际数据目录后复制。常规安装的凭据仍依赖系统凭据存储，跨设备迁移秘密应使用加密导出；便携配置则需要完整密钥库和主密码。

## 命令行

CLI 同步需要独占配置，运行前关闭桌面应用：

```sh
oxideterm cloud-sync sync --dry-run --json
oxideterm cloud-sync sync --yes --json
```

预演会准备远端合并预览，不应用或发布。单独的 `preview` 和 `diff` 命令查看缓存状态。备份与诊断命令见 [CLI 伴侣工具](/zh-hans/docs/features/cli/)。
