---
title: 端口转发
description: 本地、远程和动态端口转发，支持智能远程端口检测和自动恢复。
---

OxideTerm 支持本地、远程和动态 SSH 端口转发，并可检测远端监听端口。可以从已连接主机创建规则，也可以在会话管理中保存独立 SSH 隧道。

## 转发类型

### 本地转发 (-L)

将本地机器的端口通过 SSH 隧道转发到远程主机。

```
本地端口 ──SSH 隧道──► 远程主机:端口
```

**使用场景：**
- 在本地浏览器中访问远程 Web 服务（如端口 8888 上的 Jupyter Notebook）
- 通过安全隧道连接远程数据库（MySQL、PostgreSQL）
- 访问防火墙后的内部 Web UI

### 远程转发 (-R)

将远程服务器的端口转发回本地机器。

```
远程端口 ◄──SSH 隧道── 本地主机:端口
```

**使用场景：**
- 将本地开发服务器暴露给远程环境
- 与远程网络上的同事分享本地服务
- Webhook 开发——在远程服务器接收回调并转发到本地应用

### 动态转发（SOCKS5 代理）(-D)

通过 SSH 隧道创建 SOCKS5 代理，实现灵活的流量路由。

```
本地 SOCKS5 端口 ──SSH 隧道──► (任意远程目标)
```

**使用场景：**
- 通过远程服务器路由浏览器流量
- 无需逐个端口转发即可访问多个内部服务
- 从远程服务器视角进行网络调试

## 独立 SSH 隧道

需要转发端口，但不需要打开终端时，使用独立隧道。

1. 打开**新建连接 → 高级连接 → SSH 隧道**。
2. 填写名称和可选分组，选择承载隧道的已保存 SSH 主机。
3. 选择**本地**、**远程**或**动态（SOCKS5）**，填写绑定地址和端口；本地、远程转发还需填写目标主机和端口。
4. 点击**保存**留待以后使用，或点击**保存并启动**立即连接。
5. 需要每次启动 OxideTerm 时连接，才启用**应用启动时连接**。认证仍可能需要用户输入。

在**会话管理**中管理保存的隧道，在**端口转发**中查看运行规则。隧道独立使用 SSH 连接，关闭其他终端不会停止隧道；不再需要时应主动停止。退出 OxideTerm 会停止隧道，目前不会作为独立后台服务继续运行。

隧道配置支持云同步和加密 `.oxide` 导入导出，在线连接状态不会同步。换到另一台设备后，启动前应确认关联的 SSH 主机、认证信息及本地绑定端口。

## 智能远程端口检测

OxideTerm 自动检测远程服务器上正在监听的服务。**远程监听端口** 面板显示：

- **端口号**和绑定地址
- **进程名称**（通过 `/proc` 或 `ss` 获取时）
- **一键转发** — 点击 **Forward** 即可创建本地转发，端口自动填充

无需记忆端口号或手动配置转发规则。

## 快捷转发

将常用转发固定为 **快捷转发** 以便即时访问。它们以彩色标签形式显示在端口转发标签页顶部。一键启动，一键停止。

## 管理

- 查看所有活动转发的**状态**、**本地/远程地址**和**实时流量统计**（字节进/出）
- **启动 / 停止**单个转发
- **编辑**转发规则（端口、绑定地址、远程主机）
- **连接错误** — 重试前检查规则状态和错误信息
- **空闲连接** — 转发的数据连接默认空闲 300 秒后关闭；转发监听器仍可继续接受新连接

## 连接归属

转发使用受管理的 SSH 连接，并拥有独立的监听器和连接任务。关闭终端只释放该终端对 SSH 的使用，不会停止其他仍在运行的转发。停止规则会结束它的转发任务；主动断开所属 SSH 连接也会中断这些转发。

## 重连行为

当连接断开并重新连接时，**重连协调器**自动恢复所有活动和挂起的端口转发：

1. **快照** — 断连前，捕获所有活动的转发规则（用户手动停止的除外）
2. **SSH 重连** — 建立新连接，获得新的 `connectionId`
3. **恢复** — 在新会话上重建每条转发规则，跳过重复项
4. **状态同步** — UI 更新显示已恢复的转发和全新的流量计数器

用户手动停止的转发**不会**自动恢复——协调器尊重用户意图。

## 状态门控

所有转发操作要求连接状态为 `active`。在 `link_down` 或 `reconnecting` 状态下，UI 禁用转发控件，防止在断开的 SSH 通道上操作。
