原生插件不是 React 组件，也不会在 WebView 中执行 JavaScript。宿主发现 `plugin.json` 包后，会按需激活由宿主拥有的进程或 Wasm 运行时。

## 从清单开始

在 `<config-dir>/plugins/com.example.hello/plugin.json` 创建清单：

```json
{
  "id": "com.example.hello",
  "name": "Hello Native",
  "version": "0.1.0",
  "runtime": { "kind": "wasm", "entry": "plugin.wasm" },
  "contributes": {
    "sidebarPanels": [{ "id": "hello", "title": "Hello", "icon": "panel-left" }],
    "settings": [{ "id": "message", "type": "string", "default": "Hello", "title": "Message" }]
  }
}
```

`runtime.kind` 支持 `wasm`、`process` 和 `manifest-only`。每个运行时都需要显式入口路径。旧 `main.js` 包仅用于迁移诊断，原生应用不会执行它。

## 进程插件

进程插件使用宿主拥有的 stdin、stdout 和 stderr。stdout 每行输出一个带版本的 JSON 对象；stderr 专用于诊断。宿主发送激活、事件、命令、健康检查和停止请求，插件使用相同的请求标识回应。

```text
宿主 stdin -> activate / sendEvent / dispatchCommand / health
插件 stdout -> runtimeReady / 贡献项注册 / 响应
插件 stderr -> 诊断信息
```

## 原生界面和宿主 API

插件可声明标签页、侧栏面板、设置、命令、快捷键、上下文菜单、状态项、终端钩子、订阅、AI 工具和传输方式。标签页和面板注册声明式 schema，由 GPUI 绘制；插件不会获得 GPUI 元素或 CSS 注入权限。

激活时，宿主会提供生效的能力和允许调用的宿主 API。只请求插件实际需要的权限。凭据应放在宿主的凭据感知流程中，绝不能写入协议帧或诊断日志。

## 开发和测试

1. 运行 `oxideterm paths --json`，将插件包放入返回的 `plugins` 目录。
2. 在桌面端“插件管理器”中启用或重新加载插件。
3. 进程协议输出只写 stdout，诊断只写 stderr。
4. 使用 `oxideterm plugins list --json` 和 `oxideterm plugins enable <id> --dry-run` 做无界面检查。

原生插件协议会随应用演进。发布插件前，请针对当前发布版本验证。
